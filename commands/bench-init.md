# bench-init

You are scaffolding a `.build-bench.yml` spec file for the `oxy-build-bench` evaluation
framework. The spec defines what database to benchmark against, what the builders should
build, and what the evaluation criteria are. It is the input to `/oxy-skills:oxy-build-bench`
— it does not run any evaluation itself.

## Step 1: Gather Information

Ask the user for the following in a **single message** — do not ask one at a time:

1. **Benchmark name** — short display name (e.g. "Pokehouse Restaurant Analytics")
2. **Database type** — `clickhouse`, `snowflake`, `duckdb`, or other
3. **Connection details** — either:
   - The env var name holding the connection string (e.g. `CLICKHOUSE_URL`), or
   - Individual vars for host, user, password, database
4. **Build prompt** — ask them to describe the database in a few sentences:
   > "What domain does the database cover, what do the main tables track, and what kinds
   > of questions should the analytics agent be able to answer?"
5. **Builders** — which builders to compare. Present this default and ask if they want
   to change it:
   ```yaml
   - name: build-instance
     invoke: command
     ref: skills/commands/build-instance.md
   - name: build-agent
     invoke: manual
   ```

## Step 2: Infer required_semantics from Schema

Once you have connection details, query the database schema to discover tables and columns.

**ClickHouse:**
```bash
curl -s -X POST "http://<user>:<password>@<host>/?database=<database>" \
  -d "SELECT table, name AS column, type FROM system.columns WHERE database = '<database>' ORDER BY table, position"
```

**Snowflake / DuckDB / generic:**
```sql
SELECT table_name, column_name, data_type
FROM information_schema.columns
ORDER BY table_name, ordinal_position
```

Scan the results for these patterns and generate `required_semantics` entries only for
patterns that match tables actually present:

| Pattern | Suggested entry |
|---------|----------------|
| Table with `amount`, `revenue`, `sales`, or `total` numeric columns | `topic_contains: sales` / `must_have_measures: [revenue]` |
| Table with `labor_cost`, `hours`, `wages` numeric columns | `topic_contains: labor` / `must_have_measures: [labor_cost]` |
| Table with `order_id`, `order_count`, or similar transaction counts | `topic_contains: order` / `must_have_measures: [total_orders]` |

Add a comment next to each entry noting which table it was inferred from.

`required_artifacts` is always `[topic, agent, view]` — no need to ask.

## Step 3: Write the Spec File

Output path: `benchmarks/<slug>/<slug>.build-bench.yml`
where `<slug>` = benchmark name lowercased, spaces replaced with hyphens.

Write the file with this structure:

```yaml
# <benchmark name> — Build Benchmark Spec
# Generated by /oxy-skills:bench-init on <date>
#
# Run the benchmark:
#   /oxy-skills:oxy-build-bench benchmarks/<slug>/<slug>.build-bench.yml
#
# Evaluate pre-built dirs:
#   /oxy-skills:oxy-build-bench benchmarks/<slug>/<slug>.build-bench.yml \
#     --eval-only --dir-a /path/to/dir-a --dir-b /path/to/dir-b

name: "<benchmark name>"
description: >
  <one sentence summarising the build prompt>

database: <type>
connection_env: <env var>   # host+port encoded as http://host:port

build_prompt: |
  <build prompt verbatim from user>

builders:
  <builders from user — default or customised>

required_artifacts:
  - type: topic   # at least one *.topic.yml
  - type: agent   # at least one *.agent.yml
  - type: view    # at least one *.view.yml

required_semantics:
  <inferred entries, each with a comment noting the source table>

# eval_cases: intentionally absent — the benchmark runs in Level 1 (consistency)
# mode by default, which requires no expected answers.
#
# To upgrade to Level 2 (correctness), add human-verified cases here after running
# oxy-test-drafter on a built instance to bootstrap expected answers:
#
# eval_cases:
#   - name: total-revenue
#     prompt: "What is total revenue?"
#     expected: "Total revenue across all locations is approximately $X."
```

## Step 4: Confirm and Hand Off

After writing the file, tell the user:
- The path it was written to
- How to run the benchmark:
  ```
  /oxy-skills:oxy-build-bench benchmarks/<slug>/<slug>.build-bench.yml
  ```
- That the benchmark will run in Level 1 (consistency) mode by default — no expected
  answers needed. To upgrade to Level 2 (correctness), run `oxy-test-drafter` on the
  built instance and add the verified cases to `eval_cases` in the spec.
